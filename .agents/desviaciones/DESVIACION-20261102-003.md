# Pantalla vacía por require dinámico y verificación de arranque insuficiente

## Qué se esperaba

La evidencia proporcional de §17.0.3 debe demostrar el resultado observable.
Un arranque web funcional requiere que el navegador ejecute el bootstrap y
renderice contenido; recibir HTTP 200 no acredita ese comportamiento.

## Qué se observó

La unidad anterior comprobó compilación y HTTP 200 y declaró que el arranque
funcionaba. El usuario encontró una pantalla vacía. Se reprodujo el fallo en
una pestaña limpia, con el siguiente error de la aplicación:

```text
Error: Dynamic require of "@angular/compiler" is not supported
at http://localhost:4200/chunk-IAYMVX5O.js:24:9
at http://localhost:4200/main.js:780:1
```

`src/main.ts:1` contiene `require('@angular/compiler');` pese a existir ya un
import ESM del mismo paquete. La revisión anterior identificó esa línea en lint
pero no verificó la ejecución del navegador antes de informar el arranque.

## Evidencia

Se conservan la captura aportada por el usuario, el código de `src/main.ts`,
el log de consola leído con Browser Use y el snapshot vacío de la pestaña
limpia. Los originales complementarios y la captura final quedan en
`TEMP/atomic-calidad-20261102-002/`.

## Corrección mínima que preserva la doctrina

Se elimina únicamente el require CommonJS y se conserva un import ESM válido.
Después de compilar se recarga el navegador, se comprueba contenido visible y
la consola del nuevo arranque, y se conserva una captura del resultado.

## Lo que NO se debe hacer

No se reinstala Angular globalmente, no se cambian versiones ni se desactivan
las extensiones del usuario para atribuirles un error de la aplicación. No se
debilitan reglas de lint, no se valida de nuevo el arranque solo con HTTP y no
se modifica la autenticación para hacer coincidir pruebas obsoletas.

## Escalado

La recarga final espera explícitamente que sean visibles el encabezado y la
tabla, porque el bootstrap es asíncrono. `navegador-final.json` acredita ambos
elementos visibles y cero errores de consola posteriores a la navegación;
`atomic-ui-corregido.png` conserva la evidencia visual. La lectura inmediata
anterior a completar el render se conserva separada, sin tratarla como éxito.
La aplicación también supera sus builds y la suite completa. Se cierra la
incidencia sin cambios de dependencias ni ajustes del navegador del usuario.
